# Head Office (HO) orders cluttered the dashboards - now kept in the sheets, marked "Head Office (HO)" and hidden

- **Date:** 2026-11-16
- **Reported as:** "keep HO orders but do not show on dashboard the entire FMS just mark it Headoffice(HO)"
- **Symptom:**
  - Head Office orders (Vinculum location H01: channel N46, some N78 / N89) sat in Full Flow FMS / KASA Form like customer orders.
  - After the Order No fill of 16-Nov they showed on the POD web app under "Punched orders - not dispatched yet" (79 orders / 458 lines) and in the FMS_Dashboard counts (open GTs 137, 7,516 active lines), although nobody ships them to a customer.
- **Where:** every reader of AJ "Order Delivery Status" (GT) / BC "Order Status" (KASA) knew only Cancelled / OOS / Virtual Invoice / RTV as closed; nothing knew what an HO order is.
- **Root cause:** a missing concept. There was no HO marker and no list of HO orders, so HO lines were open lines like any other.
- **Why it wasn't caught:** HO orders only entered the sheets in numbers when the Order No fill (backup "Order No Fix Backup 2026-11-16 1539") wrote their Vinculum order numbers; before that they had no Order No and no dashboard showed them as punched.
- **Fix (user rule: keep the lines and their Order No / Order ID, mark them, hide them everywhere):**
  - **What an HO order is:** a Vinculum order whose location is H01. Read from Vinculum (`order/status`, pickupLocation), never from the prefix: channel N46 is H01 for 71 orders but N461590 and 4 more are N10 / NM1 / NM7. 81 H01 orders found among 2,273 checked (9 of them N78, 1 N89). HO2 (N88165, a different location code) is not treated as HO.
  - **Marker:** AJ (GT) / BC (KASA) = "Head Office (HO)" on every HO line that is not Delivered / Cancelled / Virtual Invoice / OOS / RTV (KASA: also Closed / Self Pickup). Those keep their own status. A row naming several orders is marked only when every one is HO. An order Vinculum shows Cancelled is not marked (Cancelled wins; VinCancelSync.js treats HO as open).
  - **HO Orders tab** (GT FMS file): Order No | Location | Is HO | Vinculum Status | Checked At | Source, one row per checked order. The dashboards read the Y rows, so an HO order is out of every list even when its lines are Delivered (the marker does not touch those).
  - **Dashboards:** "head office (ho)" is in `GTP_EXCL_STATUS`, `FF_EXCL_STATUS`, `FF_ACTION_EXCL_STATUS`, KASA `FMS_EXCLUDE`, alert.js. The HO order set rides on the holds object (non-enumerable `__ho`, GT_FMS `Pod_HeadOffice.js`, KASA_FMS `KasaOrderHolds.js`), so every place that already skips On hold orders skips HO too: pending POD, punched-not-dispatched, KASA lists, tiles, analytics, FMS_Dashboard, missing-POD alert, mail POD scan (`gtpMosPendingOrders_`). Cancel / Virtual Invoice / RTV plans see HO lines as closed.
  - **Keeping it marked:** GeneralTrade_FMS `GtHoMark.js`, hourly from `gtEnforceTemplateSharing` after `vcsSyncTick`: asks Vinculum (max 50 orders, stops at the first quota refusal) for open-line orders not yet in the HO Orders tab, then marks new HO lines. Covers the punch portal fill, GtDispatchFill and GtTeamAuto writers (none of them writes AJ / BC, so none can undo the mark; the nightly Python jobs now treat the marker as closed).
  - **Batch (guarded):** dry run 378 GT lines on 64 GTs / 0 KASA; applied run `GHM 2026-11-16 1641 batch`: 378 written, read-back clean, 0 changed meanwhile. Skipped: 53 Delivered + 2 Virtual Invoice GT lines, 9 Delivered KASA lines, 17 rows naming an HO and a non-HO order, 3 HO orders Cancelled in Vinculum. Backup = tab "HO Mark Log" of the GT FMS file (Before / After per cell, run id above). Rollback: `ghmRollback("GHM 2026-11-16 1641 batch", {dry:false})`.
  - **Effect (same data, old code vs new):** punched-not-dispatched 79 -> 14 orders (458 -> 80 lines); FMS_Dashboard open GTs 137 -> 101, active lines 7,516 -> 7,085 (-431 = 378 marked + 53 Delivered HO); pending POD unchanged (no HO line was shipped / invoiced on the sheet); KASA lists unchanged (the only 9 HO KASA lines are Delivered).
- **Tests:** GT_FMS `tests/ho-orders.test.js` (11) and `node --test tests/*.test.js` 36/36; KASA_FMS `tests/kasa-ho-orders.test.js` (4), `kasa-rtv-closed.test.js` updated; GeneralTrade_FMS `tests/gt-ho-mark.test.js` (9); nasher `tests/test_ho_marker.py` (4), pytest 192 passed.
- **Blast radius:** the HO Orders / HO Mark Log tabs are new; the dashboards read HO Orders with a try/catch (a missing tab means no HO set, as before). The hourly marker only ever writes AJ / BC on lines whose AJ / BC is blank or in progress.
- **Still open:**
  - 14 open-line orders and ~179 orders on closed lines are not checked yet (Vinculum quota hit during the scan: "code 13"); the hourly tick works through them. 17 mixed rows (HO + non-HO order in one cell) stay unmarked.
  - The punch portal keeps its own skip list: it only lists lines without an Order No, which HO lines never are, so it was not changed.
